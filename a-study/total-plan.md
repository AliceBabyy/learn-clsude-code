> **18 天螺旋式学习：先建立蓝图，再跑核心机制，再快速扫完高级能力，最后立刻做一个小项目。**

你适合：

```
顶层定位
→ 最小可运行机制
→ 修改后看到效果
→ 补充系统能力
→ 立即放进项目
→ 遇到问题再深入
```



## 18天方案

### 第一阶段：核心发动机，6天

这部分要真正理解、运行和修改。

| 天数 | 内容                 | 可见成果                        |
| ---- | -------------------- | ------------------------------- |
| 1    | s01 Agent Loop       | 看到模型自主调用Shell并继续执行 |
| 2    | 重走s01消息链        | 打印每轮消息，画完整循环        |
| 3    | s02 Tool Use         | Agent从一个工具扩展到多个工具   |
| 4    | 自定义工具           | 增加时间、HTTP或文件查询工具    |
| 5    | s03 Permission       | 危险操作被拒绝或要求确认        |
| 6    | s04 Hooks + s05 Plan | 看到调用日志和任务规划          |

完成后你已经有一个最小但完整的Agent：

```
Model + Loop + Tools + Permission + Hooks + Plan
```

这时会有明显成果，不会连续学一周仍然云里雾里。

### 第二阶段：关键运行能力，6天

这些是Agent从Demo变成可持续运行系统的关键。

| 天数 | 内容                | 核心定位               |
| ---- | ------------------- | ---------------------- |
| 7    | s06 Subagent        | 隔离复杂子任务的上下文 |
| 8    | s07 Skill           | 知识与能力按需加载     |
| 9    | s08 Context Compact | 控制上下文和Token增长  |
| 10   | 修改上下文阈值      | 亲眼观察压缩前后的差异 |
| 11   | s09 Memory          | 跨会话保存有价值的信息 |
| 12   | s14 MCP             | 通过协议接入外部工具   |

这六天结束后，你脑中的Harness应该变成：

```
Agent Loop
├── Tools与MCP
├── Permission
├── Hooks
├── Planning
├── Subagent
├── Skills
├── Context
└── Memory
```

### 第三阶段：快速建立高级能力坐标，3天

这一阶段只定位，不深挖。

| 天数 | 内容     | 只回答什么                               |
| ---- | -------- | ---------------------------------------- |
| 13   | s10～s12 | 持久任务、后台执行、定时触发分别解决什么 |
| 14   | s13      | Agent Team与Subagent有什么区别           |
| 15   | s16～s17 | Workflow与自主Agent如何组合、谁决定停止  |

不研究线程、文件锁、调度器、团队通信的实现细节。以后项目真正需要时再回来。

### 第四阶段：整合与改造，3天

| 天数 | 内容                   | 成果                           |
| ---- | ---------------------- | ------------------------------ |
| 16   | s15 Integrated Harness | 找出所有机制的组装位置         |
| 17   | 定制一个小Agent        | 删除不需要的能力，保留核心能力 |
| 18   | 验收与复盘             | README、架构图、演示和问题清单 |

最终项目不求大，可以是：

- 本地代码库分析Agent
- 文件整理Agent
- API调查Agent
- 项目文档维护Agent

至少包含：

- 两个以上工具
- 权限控制
- 最大循环次数
- Hooks日志
- 简单计划
- 一种记忆或上下文处理

## 每天的最高效结构

你应当每次都形成闭环：

```
5分钟：定位
15分钟：读核心说明
15分钟：追踪代码入口和数据流
25分钟：运行、修改、制造一个变化
10分钟：复述和记录
```

### 定位阶段先回答

开始每章之前先明确：

```
它属于Harness哪一层？
它解决什么失败场景？
重要程度是核心、增强还是高级？
输入和输出分别是什么？
```

不知道定位就不要直接钻代码。

### 每天必须出现一个变化

例如：

- 工具数量从1变成2
- 一个命令被权限规则拒绝
- 消息历史达到阈值后被压缩
- 删除记忆后Agent忘记某件事
- Subagent拥有独立messages
- MCP工具出现在工具目录中

看见行为变化，才算当天完成。仅仅读完README不算。

## Vibe Coding时代应该练什么

现在确实不需要手写每一行代码。更值钱的能力已经变成：

1. 明确问题和验收标准
2. 判断功能属于系统哪一层
3. 将需求拆成可验证的小步骤
4. 指挥Codex生成实现
5. 审查数据流和安全边界
6. 运行测试并定位失败
7. 判断生成方案是否过度设计
8. 能解释为什么这样实现

所以可以全程让Codex写代码，但每天你必须亲自承担至少一项“所有权动作”：

- 先预测代码会怎样运行
- 自己决定增加什么功能
- 要求Codex只修改一个明确位置
- 审查diff并指出风险
- 故意制造错误后定位原因
- 不看文档解释完整执行链路

你不必证明自己会打字，但必须证明自己能控制系统。

## 与Python基础怎么并行

在完成learn-py的01～09之前：

```
Python：60分钟
Agent：60分钟
```

完成01～09后：

```
Python查漏补缺：30分钟
Agent学习与实践：90分钟
```

后续遇到装饰器、异步、类型注解等语法时再精准回补，不继续线性啃完整Python教材。

最终建议就是：

> **18天完成“学习+小项目”，而不是14天纯浏览，也不是24天教程精读。**

这套方式更符合你的特点：先给顶层地图，每天产生可见行为变化，控制复杂度，快速进入项目，再由项目决定哪些细节值得深入。
