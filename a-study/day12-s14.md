### 第12天：s14 MCP Tools

今天只解决一个核心问题：

> Harness如何连接外部工具提供方、发现工具，并把它们动态接入原有Agent Loop？

建议投入 **90分钟**。其中API迁移是受控任务，核心仍是MCP工具的动态发现与分发。

### 今日定位

- 所属层：Harness的外部工具接入层
- 解决的失败场景：每接入一个外部服务都要在Agent源码中重复维护工具定义、参数和调用逻辑
- 接入位置：模型调用前动态组装工具池；工具执行时通过统一handler分发；执行前仍经过宿主权限Hook
- 重要程度：增强。不是Agent Loop成立的必要条件，但是真实Agent扩展工具生态的关键边界
- 今天停止位置：能解释“连接、发现、命名、组装、调用、回填”完整链路并完成模拟server实验；不学习真实transport和完整MCP规范

本地实现必须先认清两个边界：

1. `s14_mcp_plugin/code.py`目前仍使用Anthropic Messages API。今天先识别原机制，再迁移到OpenAI Responses API，统一使用`function_call`、`function_call_output`和`call_id`。
2. `docs`和`deploy`是进程内模拟server。`MCPClient.register()`模拟`tools/list`结果，`call_tool()`模拟`tools/call`入口；本章没有stdio、HTTP或JSON-RPC通信。
3. 迁移后的代码注释、日志、system prompt、工具描述、用户提示和错误信息使用中文；协议字段、函数名、类名、工具名及环境变量名保持英文。

### 今日可见成果

今天结束时必须亲眼看到：

1. 连接前工具池只有基础工具和`connect_mcp`
2. 调用`connect_mcp(name="docs")`后，下一轮工具池新增`mcp__docs__search`和`mcp__docs__get_version`
3. 模型通过新工具查询文档，结果仍作为普通`function_call_output`回填
4. 连接不存在的server时返回错误，但Agent Loop不崩溃
5. `deploy.status`可直接执行，而`deploy.trigger`由宿主策略要求确认；拒绝后server handler不执行

### 数据流

```text
第1轮组装工具池
→ 模型只看到基础工具和connect_mcp
→ 模型调用connect_mcp(name="docs")
→ Harness从MOCK_SERVERS创建MCPClient
→ server工具定义保存到mcp_clients
→ connect结果作为function_call_output回填
→ 第2轮重新assemble_tool_pool
→ 工具被规范化为mcp__docs__search等名称
→ 模型调用动态MCP工具
→ PreToolUse根据宿主策略检查
→ handler使用原始工具名调用MCPClient.call_tool
→ 执行结果作为function_call_output回填
→ 模型继续判断或结束
```

协议字段映射：

```text
Anthropic tool_use      ≈ OpenAI function_call
Anthropic tool_result   ≈ OpenAI function_call_output
Anthropic tool_use_id   ≈ OpenAI call_id
```
