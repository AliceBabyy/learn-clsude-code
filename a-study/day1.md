## 第一天目标

结束时能解释这条链路：

```
用户输入
→ messages
→ 调用LLM
→ 返回tool_use
→ Harness执行工具
→ 追加tool_result
→ 再次调用LLM
→ 返回最终回答
```

今天只认识这些概念：

- Model：负责判断和生成
- Client：负责调用模型API
- Messages：程序维护的对话历史
- Tool：模型可以请求的外部能力
- Agent Loop：不断调用模型、执行工具、回填结果
- Harness：承载循环、工具和运行环境的代码

## 50～60分钟：闭卷复述

关掉README，用自己的话回答：

1. 模型为什么能够操作文件？
    因为调用了tool函数，tool实际上调用了方法run_bash
2. 模型是否亲自执行了Shell命令？
    否
3. 为什么工具结果必须重新发给模型？
    因为工具不由模型直接调用，是通过执行run_bash方法
    对于智能体来时该方法就是工具，调用该方法后返回结果要作为下一次循环输入让模型知道，模型才能下一轮判断
4. `messages`是谁维护的？
    message初始再启动程序只有用户角色和提问，中间维护主要发生在方法agent_loop的while循环
5. 循环为什么能够继续？
    因为没说让停
6. 循环在什么情况下停止？
    用户输入"q", "exit", ""
7. 如果模型一直调用工具，会出现什么问题？
    会出问题啊
正确的核心理解应当是：

> 模型负责决定下一步，Harness负责执行；执行结果进入messages后，模型才能观察结果并继续判断。
